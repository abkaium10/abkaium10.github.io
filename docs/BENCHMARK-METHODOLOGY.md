# Benchmark methodology

Run `npm run benchmark`. The runner creates deterministic integer-keyed records, performs warmups, collects independent timed samples with `node:perf_hooks`, and records medians/p95, runtime, platform, host-reported CPU, dataset size, operation count, and heap-use snapshots. The Map construction median is sampled separately from repeated lookup. `public/data/benchmarks.json` contains the measurements generated by the last run; it is not a universal performance claim.

The simplified break-even model is `total = setup + operationCount × perOperation`. The published estimate uses the measured Map setup median and per-operation medians. It is unavailable if Map has no measured per-operation advantage. Measurement noise, JIT, CPU contention, memory pressure, cache behavior, and runtime versions can materially shift estimates. Heap deltas are not a reliable isolated allocation measurement and are not interpreted as one. Do not compare results across different hosts as if they were controlled.
